# ai-panel

A small web control panel for a self-hosted GPU/LLM server: power on and off through the BMC
(IPMI), a clean shutdown and reboot through a restricted host agent, model switching for
[llama.cpp](https://github.com/ggml-org/llama.cpp), schedules that switch the server off when
nobody needs it, and what it costs to run.

It is made for one kind of machine: a Proxmox host that runs llama.cpp in an LXC container,
with a BMC that speaks IPMI, ideally watched by Prometheus and Alertmanager. Each of those sits
behind a small interface, so another kind can be added without touching the rest.

## What you get

- **The dashboard:** power (from the BMC), the host's uptime and running Proxmox tasks, the
  loaded model (from llama.cpp's own `/props`), health, busy slots and decode speed, the GPUs,
  the guests, active alert silences, and the power draw, price and cost per hour right now.
- **Actions**, one at a time and each with its steps shown live: power on, shut down, reboot,
  switch the model, restart, stop or start the LLM, start or stop a guest, a read-only probe,
  and emergency BMC commands for a host that no longer answers. Power actions need the host's
  name typed to confirm; a planned stop silences its alerts first.
- **Schedules:** power off and on at set times to save power, with catch-up after the panel was
  down, holds ("keep it on until Friday"), skips, waiting for busy slots, and protected windows
  (your backups) that no stop may touch.
- **Running cost:** now, today, 7 days and this month by tariff period, the money the schedule
  saved, and its 30-day forecast. Power and price come from Prometheus or from static values (a
  time-of-use tariff in the config).
- **Activity:** an audit log of who did what, and every settings change from and to.
- **Settings** on a page generated from the settings model, and the same through a JSON API and
  a CLI, so an agent can change them too.

## Try it without hardware

```bash
docker run --rm -p 8080:8080 -e AIPANEL_DEMO=1 ghcr.io/nisesen/ai-panel:0.1
# or from a clone: docker build -t ai-panel . && docker run --rm -p 8080:8080 -e AIPANEL_DEMO=1 ai-panel
```

Open http://localhost:8080. DEMO mode simulates the BMC, the host, the LLM and two GPUs, with a
month of power history; actions take as long as a small real boot would. Nothing real is
touched, and it needs no sign-in (that is allowed only in DEMO mode).

From a clone, without Docker: `uv run aipanel --demo --state-dir /tmp/aipanel serve`.

## How it fits together

```
browser ──► your proxy (signs people in, sets user and group headers)
               │
               ▼
          ai-panel ──ipmitool──► BMC          power on, power state, emergency off
          (one     ──ssh───────► llm-ctl      on the host: status, shutdown, reboot,
          container)              (forced       llm switch, guests, probe
                                   command)
                   ──http──────► llama.cpp    /health, /props, /slots
                   ──http──────► Prometheus   GPUs, power, price; Alertmanager: silences
```

- `src/aipanel/`: the app. `backends/` holds one small interface per outside system and one
  implementation each (plus the DEMO fakes); `actions/` holds the actions, each a class in a
  registry; `runner.py`, `poller.py`, `scheduler.py` and `cost.py` do what their names say;
  `web/` is server-rendered pages with [htmx](https://htmx.org) (vendored, no CDN, no build
  step).
- `agent/llm-ctl`: the host agent, one Python file with the standard library only.
- `schema/`: the JSON Schemas of both configuration files, generated by `aipanel schema`.

## Configuration

Two files, and each setting lives in exactly one of them:

- **`config.yaml`**, the site config, is owned by git and read-only to the panel: where it
  connects, how people sign in, which actions exist, the price and power sources, protected
  windows. [examples/config.yaml](examples/config.yaml) is a commented example.
- **`settings.json`** is owned by the panel: schedules, timeouts, cooldowns, silence lengths,
  cost values, display. Change it on the settings page, through the API, or with
  `aipanel settings set schedule.enabled=true`.

[docs/configuration.md](docs/configuration.md) explains both, and how an agent edits each.
The environment: `AIPANEL_CONFIG` (the site config's path), `AIPANEL_STATE_DIR` (default
`/var/lib/aipanel`), `AIPANEL_PORT` (8080), `AIPANEL_METRICS_PORT` (9090, for `/metrics` and
`/healthz`), `AIPANEL_DEMO=1`.

## Security

The panel can switch a machine off, so it refuses to start without authentication: a proxy you
control signs people in and passes their name and groups in headers. Read
[docs/security.md](docs/security.md) before you deploy it, and [docs/agent.md](docs/agent.md)
for the restricted account on the host. Report vulnerabilities privately, as
[SECURITY.md](SECURITY.md) describes.
